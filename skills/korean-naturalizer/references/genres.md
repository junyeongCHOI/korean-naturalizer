# 글 종류별 기준

독자와 문서의 목적이 일반적인 문체 취향보다 우선한다. 사용자가 지정한 말투와 제출 형식이 있으면 따른다.

| 종류 | 앞에 둘 내용 | 말투와 구성 | 특히 지킬 내용 |
| --- | --- | --- | --- |
| README, 사용 안내 | 무엇을 하는지, 어떻게 시작하는지 | 짧은 설명, 실행 가능한 예시, 필요한 제목과 목록 | 실제 기능, 명령어, 경로, 지원 범위 |
| 고객 공지 | 영향받는 기능, 시각, 필요한 행동 | 정중하고 분명한 합니다체 | 중단 가능성과 확정의 구별, 조건, 시간대 |
| 업무 메일 | 요청이나 결론과 그 이유 | 관계에 맞는 인사와 부탁 | 책임 주체, 기한, 승인 여부, 요청 강도 |
| 보고서 | 핵심 결과와 판단 근거 | 일관된 서술체, 비교는 표로 | 사실과 해석의 구별, 수치, 출처 |
| 학술문, 초록 | 연구 목적, 방법, 결과 | 해당 분야의 용어와 제출 형식 | 연구 범위, 통계적 의미, 한계, 인과 추론 범위 |
| 블로그, 에세이 | 주제에 맞는 관점이나 장면 | 제공된 글쓴이의 말투와 호흡 | 실제 경험과 의견, 의도적인 반복 |
| 대화, 설명 | 질문에 대한 답 | 대화의 높임에 맞춘 짧은 설명 | 듣는 사람이 알아야 할 전제와 용어 |
| 화면 문구 | 사용자가 할 일이나 현재 상태 | 짧고 익숙한 표현, 서비스의 기존 말투 | 버튼의 실제 동작, 오류와 복구 조건 |
| 자기소개, 지원서 | 본인의 역할, 행동, 결과 | 지원 목적에 맞는 구체적인 서술 | 실제 경험, 기여 범위, 본인이 한 일과 팀이 한 일의 구별 |
| 연설, 축사 | 청중과 행사에 맞는 메시지 | 소리 내어 읽기 쉬운 문장, 필요한 반복 | 실제 인물, 관계, 성과, 의도적인 강조와 호칭 |

## 새 글을 쓸 때

한국어로 핵심 메시지를 정한 다음 필요한 근거와 행동을 붙인다. 기본 골격은 출발점일 뿐 모든 글에 '서론, 장점 세 가지, 밝은 전망'을 붙이지 않는다.

- README: 도구의 기능 -> 설치나 시작 방법 -> 실제 사용 예 -> 필요한 제한사항.
- 공지: 무슨 일이 생기는지 -> 언제, 어디에 영향을 주는지 -> 사용자가 할 일.
- 설명: 질문에 답하기 -> 필요한 이유나 작동 방식 -> 이해를 돕는 예시.

주어진 사실이 부족하면 작성 가능한 부분부터 쓴다. 속도, 보안, 호환성, 무료 여부처럼 확인되지 않은 장점을 홍보 문구로 채우지 않는다.

주제에 따라 결론부터 쓰는 것이 어색하면 제공된 장면, 사건으로 시작할 수 있다. 글을 생생하게 만들려고 날짜, 등장인물, 감상을 지어내지 않는다. 문서가 충분히 끝났다면 별도의 밝은 전망이나 교훈을 붙이지 않는다.

원하는 문체를 구체적인 작성 방법으로 옮긴다. 설명문은 기능이나 결론을 먼저 쓰고 필요한 이유와 조건을 잇는다. 짧은 대화는 지금 필요한 답이나 질문부터 쓴다. 문단은 하나의 설명 단위로 묶는다. 실제 상황에 필요하지 않은 설명이나 추가 질문으로 길이를 늘리지 않는다.

## 기존 글을 고칠 때

먼저 수정할 범위를 구별한다.

- **맞춤법, 서식만:** 오탈자, 띄어쓰기, 요청받은 서식만 고친다. 어휘와 문장 구성은 유지한다.
- **문장 다듬기:** 어색한 조사, 서술어, 수식, 반복을 그 구간에서 고친다. 전체를 새 글로 바꾸지 않는다.
- **구성까지 다듬기:** 요점이 뒤에 묻히거나 문단이 중복되면 순서를 조정한다. 이동한 조건, 예외, 인용의 연결을 다시 확인한다.
- **검토만:** 문제가 되는 원문 구절과 이유, 수정안을 함께 제시한다. 그 표현이 실제로 이 문맥에서 왜 어색한지 설명한다.

격식이 높다는 이유로 대화체로 바꾸지 않고, 친근하다는 이유로 속어를 넣지 않는다. 특정 비율만큼 고쳐야 한다는 목표도 두지 않는다. 이미 자연스러우면 원문을 유지한다.

요약 요청을 받으면 정보를 선별할 수 있다. 표현 교정만 요청받았다면 세부 사항을 덜어내는 요약을 하지 않는다. 두 요청이 함께 있으면 조건, 수치, 예외를 우선 보존하며 줄인다.

## 글쓴이의 말투를 맞출 때

견본이 있으면 아래 특징을 읽고, 새 글의 목적과 맞는 범위에서 따른다. 분석 내용을 매번 사용자에게 보고할 필요는 없다.

| 살필 특징 | 적용 방법 |
| --- | --- |
| 종결과 높임 | 합니다체, 해요체, 한다체와 독자와의 거리를 유지한다. 대화, 인용 속 다른 화자의 말투는 따로 보존한다. |
| 길이와 호흡 | 짧게 끊는지, 여러 생각을 이어 가는지 본다. 문장 수와 길이 분포를 기계적으로 복제하지 않는다. |
| 어휘와 축약 | '좀, 근데, 했어요' 같은 익숙한 말을 이유 없이 격상하지 않는다. 속어, 사투리, 외래어도 사용자 요청과 독자를 고려한다. |
| 설명의 밀도 | 전제를 어느 정도 생략하는지, 용어를 얼마나 풀어 쓰는지 맞춘다. 필요한 설명까지 빼지는 않는다. |
| 관점과 태도 | 실제 1인칭, 비판의 강도, 망설임, 유머, 곁말을 살린다. 없던 의견, 감정을 만들지 않는다. |
| 구성과 강조 | 장면, 질문, 반복이 글의 중심인지 본다. 상투적으로 보인다는 이유만으로 의도적인 장치를 모두 지우지 않는다. |

견본은 말투의 근거다. 견본 속 수치, 경험, 인용, 직업, 인간관계를 새 글의 사실로 쓰지 않는다. 견본이 없으면 기존 글의 목소리를 기준으로 삼는다. 새 글에서만 독자와 목적에 맞는 기본 말투를 정한다.

글쓴이가 답을 내리지 않은 고민, 서로 충돌하는 감정, 해소되지 않은 긴장도 글의 일부다. 이를 깔끔한 교훈이나 긍정적인 결말로 봉합하지 않는다. 개인적인 글에 없는 유머, 1인칭, 여담을 보태 개성을 만들지도 않는다.

제공된 견본에서 실제 용도와 가까운 문장을 참고한다. 서로 다른 장르나 말투의 견본을 한 글에 무작정 섞지 않는다. 견본이 없을 때는 아래 완성 예문에서 목적에 맞는 구성을 참고할 수 있다.

## 분량을 맞출 때

분량 요청이 없으면 원문의 고유한 정보와 설명의 밀도를 유지한다. 군더더기를 줄일 수는 있지만 길이를 줄이는 일 자체를 목표로 삼지 않는다.

- **줄이기:** 중복된 예고, 요약, 같은 뜻의 수식, 우회 구문부터 줄인다. 다음으로 같은 내용을 묶는다. 사실, 조건, 예외, 특이한 구체적 내용은 표현 교정만으로 삭제하지 않는다. 요약을 요청받았으면 목적에 맞춰 정보를 선별한다.
- **늘리기:** 원문에 있는 사실의 관계, 절차, 조건을 풀어 설명한다. 제공된 사례를 더 자세히 설명할 수는 있지만, 새 수치, 사례, 성과, 경험으로 채우지 않는다. 같은 말 반복이나 막연한 전망으로 분량을 늘리지 않는다.
- **길이 확인:** '자'인지 '어절'인지 구별하고, 별도 지정이 없는 글자 수는 공백 포함으로 센다. 제목, 본문 등 계산할 범위를 정한다. 정확한 분량은 도구로 실제로 세며, '내외'와 '정확히'를 구별한다. 사용자가 정한 허용 범위를 우선하고 '정확히 N자'에 임의의 오차를 두지 않는다.

짧게 써 달라는 요청에는 현재 목적에 필요한 내용과 요청한 분량을 기준으로 줄인다. 한 문장이나 발화의 길이를 조절할 수 있지만, 특정 어절 수를 모든 장르의 기본값으로 두지 않는다. 짧아졌다는 이유만으로 더 자연스러워졌다고 판단하지 않는다.

의미와 분량을 함께 지킬 수 없으면 어느 조건이 충돌하는지 짧게 알린다. 없는 사실을 만들어 목표 길이를 맞추지 않는다.

## 완성 예문

아래는 가상의 작성 상황에 맞춘 완성 예문이다. 가까운 목적의 예문에서 정보 순서, 말투, 설명의 밀도를 참고한다. 제품명, 기능, 날짜, 경험, 감정은 현재 입력의 내용으로 정하며, 예문의 사실을 가져오지 않는다. 문장 수와 표현을 모든 글의 틀로 고정하지 않는다.

### README 소개

작성 조건: '갈피'는 로컬 Markdown 파일을 HTML로 변환하는 도구다. 명령은 `galpi guide.md --output guide.html`이며 변환 중 외부와 통신하지 않는다. 합니다체로 기능과 실행 방법을 소개한다.

완성 예문:

갈피는 컴퓨터에 있는 Markdown 파일을 HTML로 변환하는 도구입니다. 변환 중에는 외부와 통신하지 않습니다.

다음 명령으로 `guide.md`를 `guide.html`로 변환합니다.

```sh
galpi guide.md --output guide.html
```

## 짧거나 특수한 글을 다룰 때

- 한두 문장에는 문서 전체의 반복, 리듬 기준을 적용하지 않는다. 그 문장에서 실제로 불분명한 표현만 고친다.
- 한국어와 다른 언어가 섞여 있으면 한국어 문장을 다룬다. 외국어 인용, 제품명, 코드는 유지하고, 번역 요청이 있을 때만 별도로 번역한다. 설명 속 장식적인 영어와 식별에 필요한 영어를 구별한다.
- 제목, 버튼, 표 머리글은 완전한 문장일 필요가 없다. 짧게 만들더라도 실제 동작, 부정, 사용 조건이 바뀌지 않게 한다.
- 시, 소설, 에세이에서는 화자별 말투, 장면의 순서, 의도적인 비문, 반복, 중심 비유를 먼저 읽는다. 설명문용 지침으로 개성을 평준화하지 않는다. 교정 요청의 범위를 따른다.
- 맞춤법이 반듯하거나 한자어, 목록, 줄표가 있다는 사실만으로 고칠 필요는 없다. 문체에서 글의 작성 주체를 추정하지 않는다.

## 자연스러움과 정확성이 충돌할 때

학술, 법률, 계약, 정책 문장은 표현을 짧게 만드는 과정에서 뜻이 바뀌기 쉽다. 정의와 정해진 문구는 유지하고 주변 설명을 다듬는다. 법률 판단이나 사실 검증을 했다고 보고하지 않는다.

'통계적으로 유의하지 않았다'는 결과를 '차이가 없다'나 '효과가 없다'로 바꾸지 않는다. 쉽게 설명하더라도 원문의 수치와 해석의 한계를 유지한다.

정확한 길이와 의미 보존을 동시에 만족할 수 없다면 사실을 바꾸어 분량을 맞추지 않는다. 어떤 정보가 길이를 차지하는지 짧게 알린다.
